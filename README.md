# 三线学习训练器

这是一个本地 Web 学习程序，面向三个目标。当前版本以"智能模式 + 短文阅读驱动"为核心，用阅读理解带动词汇和语法，再通过题目检查是否真的会用。

- 日语：以《大家的日语》第 16 课为当前基线（掌握约 40%），逐步向 JLPT N1 推进。
- 英语：以 IELTS 6.0 为起点，补土木工程和 AI 学术英语（仅阅读词汇方向，不做语法子模式）。
- 《逻辑哲学论》：从核心概念、概念关系和入门读法开始。

## 大家的日语资料

日语学习资料来自 `minasang` 目录下的《大家的日语》PDF：

- `minasang/本册.pdf`：教材正文（扫描型 PDF，需 OCR 获取文本）
- `minasang/文法.pdf`：句型与语法说明

当前基线：第 16 课，第 1-16 课总体掌握约 40%。教材 PDF 仅作本地个人学习使用，不会把完整教材文本写进公开仓库。

## 使用

直接双击 `start-learning.bat` 一键启动，或运行 `node dev-server.mjs` 后打开 `http://127.0.0.1:8787/`。进度会保存在浏览器的 `localStorage` 里。

在 iPhone 上使用时，建议用 Safari 打开后添加到主屏幕。页面已经适配安全区和底部操作栏，练习时主要点击底部的提交、忘了、模糊、会了。

## 智能模式与三项主交互

界面不再有"今日到期/弱项加练/混合挑战"等模式切换，只保留一个「智能模式」入口。学习任务分为三项：

### 日语（三项）

1. **短文阅读**：基于《大家的日语》第 1-16 课词汇和句型生成的原创短文（3-5 句），逐句展开假名、中文、语法点和关键词。点击词语收藏到生词本，点击语法点收藏到语法银行。支持 AI 实时追问。
2. **词汇题**：来源为第 1-16 课词汇 + 阅读中收藏的词 + 标记忘记的词。题型包括选择中文意思、看假名选词、看中文输入日语、语境填空。
3. **语法题**：来源为第 1-16 课基础句型 + 阅读中收藏的语法点。题型包括选择正确接续、看中文选句型、改写句子、在短句中补全语法结构。当前阶段重点：て形、ない形、普通形、助词、授受/许可/正在进行/连接句。

### 英语（两项）

1. **短文阅读**：阅读短句/短文，在语境中积累词汇。
2. **词汇题**：来源为阅读中收藏的词 + 工程/AI/IELTS 词汇。

英语不做语法子模式。

## 智能推荐权重

日语（Minna 教材驱动）：
- 短文阅读：50%
- 词汇题：30%
- 语法题：20%

英语（阅读词汇驱动）：
- 短文阅读：60%
- 词汇题：40%

## 课次推进规则

学习进度不固定停在第 16 课。系统根据词汇、语法、阅读掌握度和复习保持率自动判断是否推进：

- 总掌握度 < 50%：不推进，集中补当前课和前置课
- 50% ≤ 掌握度 < 65%：稳定当前课，允许少量下一课 preview
- 65% ≤ 掌握度 < 75%：推进准备，短文可混入 10-20% 下一课内容
- 掌握度 ≥ 75%：正式推进到下一课

推进还需满足安全条件（忘词比例 ≤ 25%、忘语法比例 ≤ 30%、核心语法至少完成 2 轮复习等）。每周复盘和策略调整记录在 `WEEKLY_UPDATE_PLAN.md`。

## 日语 N1 一年路线

当前路线以 `2026-07-06 → 2027-07-06` 为一年目标窗口，现阶段先巩固《大家的日语》第 1-16 课，再逐步向 N1 推进。

- 第 1-8 周：补地基，N5/N4 → N3，重点是变形、助词、基础长句和短文复述。
- 第 9-20 周：上坡，N3 → N2，重点是中级语法网、接续词、长句切分和听力关键词预判。
- 第 21-36 周：主攻，N2 → N1，重点是 N1 高频语法、论说文结构、漢字語和影子跟读。
- 第 37-48 周：成套，N1 综合演练，重点是限时阅读、听力场景反应和错因归类。
- 第 49-52 周：冲刺，模考与压缩复盘，减少新内容，稳定节奏。

在「进度」页查看年度路线。

## 日语阅读实验室

日语学习以阅读短文为主入口：

1. 在「日语 → 智能模式 → 短文阅读」打开阅读卡。
2. 先读完整短文，再看每句的假名、中文、语法点和关键词。
3. 点击词语 chip 收藏生词；也可以手动选中文本后点「收藏选中文本」。
4. 点击语法点 chip 收藏到语法银行。
5. 在阅读卡底部直接问 AI，例如"这句为什么用一方で？"、"按我现在水平改写下一段"。
6. 生词本和语法银行里把词/语法点标成「忘了」或「掌握」；AI 生成下一篇短文时会优先考虑这些边界。

电脑端建议双击 `start-learning.bat` 后使用。DeepSeek API 更快更准；本地 `deepseek-r1:8b` 可以离线用，但速度和日语解析稳定性取决于电脑性能。

## 放到 iPhone

电脑本地文件路径 `D:\codex\学习程序\index.html` 不能直接在 iPhone Safari 打开。推荐三种方式：

1. 临时在同一 Wi-Fi 下使用：
   在电脑这个目录运行 `$env:HOST="0.0.0.0"; node dev-server.mjs 8787`，用 `ipconfig` 找电脑 IPv4 地址，然后在 iPhone Safari 打开 `http://电脑IP:8787/index.html`。

2. 添加到主屏幕：
   iPhone Safari 打开页面后，点分享按钮，选择"添加到主屏幕"。本地 Wi-Fi HTTP 可以作为快捷方式使用；如果想要更完整的离线缓存，建议把文件放到 HTTPS 页面上，例如 GitHub Pages。

3. 真正离线/PWA：
   项目已经包含 `manifest.webmanifest`、`service-worker.js` 和 `apple-touch-icon.png`。在 HTTPS 环境打开后，Safari 添加到主屏幕会更接近 App，并缓存核心文件。Service Worker 对页面和脚本采用 network-first：联网时总会拿到你最新发布的版本，断网时回退到缓存，所以更新代码后手机端不会一直卡在旧版本。

4. 推荐长期方案：GitHub Pages
   把这些文件推到 GitHub 仓库，并开启 GitHub Pages。之后 iPhone 直接打开 `https://你的用户名.github.io/仓库名/`，在电车上也能使用，不需要局域网。

   基本流程：
   - 新建一个 GitHub 仓库，例如 `learning-trainer`。
   - 把 `index.html`、`app.js`、`styles.css`、`manifest.webmanifest`、`service-worker.js`、`icon.svg` 推上去。
   - 在仓库 `Settings → Pages` 中选择 `Deploy from a branch`，分支选 `main`，目录选 `/root`。
   - 等 GitHub Pages 给出网址后，用 iPhone Safari 打开并"添加到主屏幕"。

## 手机-电脑同步

手机和电脑的浏览器各自保存一份 `localStorage`，不会自动互通。每天可以这样同步：

1. 在电脑或手机点"数据同步 → 生成备份"。
2. 点"复制"或"下载"，用 AirDrop、备忘录、微信文件、iCloud Drive 等方式传到另一台设备。
3. 在另一台设备打开页面，把备份文本粘贴到"备份文本"，点"导入并合并"。

导入是合并式的：自定义题、历史、进度、生词和语法点会尽量保留两边较新的版本。

### GitHub 自动同步

现在也支持 GitHub Gist 自动同步，适合电车上使用。

思路是：

- GitHub Pages 放网页。
- 私有 GitHub Gist 放学习进度 JSON。
- 手机和电脑打开同一个网页后，联网时自动"拉取合并 → 上传"。

设置步骤：

1. 在 GitHub 创建一个 token：
   `Settings → Developer settings → Personal access tokens`。

2. 如果用 classic token，只勾选 `gist` 权限即可。

3. 在网页的"数据同步 → GitHub 云同步"里粘贴 token。

4. 第一次使用点"创建云端"，程序会创建一个私有 Gist 并保存 Gist ID。

5. 之后保持"联网时自动同步"开启。答题、收藏生词/语法点后会自动上传；电脑打开页面后会自动拉取。

安全边界：

- Token 只存在当前浏览器的 `localStorage`，不会写进"生成备份"的 JSON。
- 不要把 token 发给别人，也不要把带 token 的浏览器配置截图公开。
- 如果你担心 token 暴露，可以只用手动"生成备份/导入并合并"。

## AI 接入说明（本地模型 / DeepSeek 出题）

本地规则推荐不需要联网，也不会上传你的学习记录。

项目自带一个**本地 AI 代理**（`proxy/ai-proxy.mjs`），可在「本地模型 / DeepSeek API」之间切换：DeepSeek 的 key 只留在你电脑上、不进前端不进仓库；本地模型默认使用 Ollama 的 `deepseek-r1:8b`，完全离线、不需要密钥。

简要用法（详见 [`proxy/README.md`](proxy/README.md)）：

```bash
# 在电脑上启动代理（需 Node 18+）
start-learning.bat                              # 一键启动网页 + AI 代理 + 检查本地 DeepSeek 8B
node proxy/ai-proxy.mjs                            # 会自动读取 .env 里的 DeepSeek key
DEEPSEEK_API_KEY=你的key node proxy/ai-proxy.mjs   # 也可以临时覆盖
AI_PROVIDER=local node proxy/ai-proxy.mjs          # 用本地 deepseek-r1:8b（先装好 Ollama）

# 然后网页里在「AI 出题（本地代理）」面板选好来源，点生成
```

`start-learning.bat` 会检查 Ollama；如果 Ollama 已安装但没有 `deepseek-r1:8b`，会自动执行 `ollama pull deepseek-r1:8b`，首次下载会比较慢。

设计思路：在**电脑上**生成题，生成的题进入题库并随 GitHub Gist 同步到手机，手机端直接练习，不需要接触模型密钥。注意发布版是 HTTPS 页面，部分浏览器会拦截它访问本地 http 代理；如遇到这种情况，用 `node dev-server.mjs` 起本地网页再生成即可。

### 学习诊断（DeepSeek 错因分析）

代理也支持 `POST /diagnose` 端点，把近期的答题数据（错题、学习档案）发给 DeepSeek 做深度分析：

- 返回**问题模式诊断**（如"汉字读音持续出错"、"は/が 助词混淆"）+ **改进建议** + **针对性练习题**（最多 6 张）。
- 诊断结果和生成的题存入本地状态，随 GitHub Gist 同步到手机。
- 手机端在「练习」视图直接查看诊断结果，不需要代理。
- 建议数天诊断一次，积累一定答题数据后再做效果最好。

用法：电脑上双击 `start-learning.bat`，网页里打开「学习诊断」面板，点「生成诊断」。
